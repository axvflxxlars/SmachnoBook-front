# SmachnoBook — фронтенд

Простий фронтенд на HTML, CSS і JavaScript (без фреймворків) для сайту з
рецептами SmachnoBook. Дані отримує з REST API бекенду, авторизація працює
через JWT.

Бекенд-репозиторій: [axvflxxlars/SmachnoBook](https://github.com/axvflxxlars/SmachnoBook)

## Сторінки

| Сторінка        | Хто бачить              | Що на ній                                                       |
| --------------- | ----------------------- | --------------------------------------------------------------- |
| `index.html`    | усі                     | Список рецептів з пошуком за назвою                             |
| `login.html`    | лише неавторизовані     | Вхід                                                            |
| `register.html` | лише неавторизовані     | Реєстрація з повідомленнями про помилки під кожним полем        |
| `profile.html`  | лише авторизовані       | Профіль, додавання рецепта, мої рецепти з видаленням            |
|                 | лише адміністратор      | Додатково на `profile.html`: створення категорії               |

## Як працює авторизація

- **Логін.** Після успішного входу (`POST /auth/login`) фронтенд зберігає
  `access`- і `refresh`-токени та дані користувача в `localStorage`.
- **Запити.** Усі запити до API йдуть через функцію `apiFetch` з `auth.js`.
  Вона додає заголовок `Authorization: Bearer <access>`.
- **Оновлення токена.** Access-токен живе 5 хвилин. Коли сервер відповідає
  `401`, `apiFetch` надсилає refresh-токен на `POST /auth/refresh`, зберігає
  новий access-токен і повторює запит. Користувачу не потрібно логінитися
  знову. Якщо кілька запитів отримали `401` одночасно, токен оновлюється
  лише один раз.
- **Прострочений refresh-токен.** Якщо оновити токен не вдалося, фронтенд
  видаляє токени. Публічні сторінки працюють далі як для гостя, а захищена
  сторінка перенаправляє на логін.
- **Logout.** Кнопка «Вийти» видаляє токени й дані користувача з
  `localStorage` і повертає на головну.

### Поведінка сторінок

- Неавторизованого користувача, який відкриває `profile.html`, перенаправляє
  на `login.html?next=profile.html`.
- Після логіну (або реєстрації) користувача повертає на сторінку з параметра
  `next`. Дозволені лише сторінки цього сайту, тому через `next` не можна
  перенаправити на чужий сайт.
- Авторизованого користувача, який відкриває `login.html` або
  `register.html`, перенаправляє на сторінку з контентом.
- Неавторизований користувач бачить у шапці кнопки «Увійти» та
  «Реєстрація», авторизований — своє ім'я та кнопку «Вийти».

## Як запустити проєкт

1. Запустіть бекенд (інструкція в README бекенд-репозиторію). Він має
   працювати за адресою **http://127.0.0.1:8000**. Щоб перевірити функції
   адміністратора, створіть його командою `python manage.py createsuperuser`.
2. У папці цього репозиторію запустіть статичний сервер:

   ```bash
   python -m http.server 5500
   ```

3. Відкрийте у браузері **http://127.0.0.1:5500**.

| Частина  | Адреса                       |
| -------- | ---------------------------- |
| Фронтенд | http://127.0.0.1:5500        |
| Бекенд   | http://127.0.0.1:8000/api/v1 |

Адреса бекенду задана константою `API_URL` на початку `auth.js`.
Якщо відкривати фронтенд за іншою адресою (наприклад,
`http://localhost:5500`), її потрібно додати до `CORS_ALLOWED_ORIGINS`
у налаштуваннях бекенду.

### Як перевірити оновлення токена

Access-токен живе 5 хвилин. Увійдіть, відкрийте вкладку **Network** в
інструментах розробника, зачекайте понад 5 хвилин і додайте рецепт. У
списку запитів буде `POST /recipes` зі статусом `401`, потім
`POST /auth/refresh` і повторний `POST /recipes` зі статусом `201`.
